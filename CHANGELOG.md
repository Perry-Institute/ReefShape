# 🪸 CHANGELOG – ReefShape

## [v1.3] – June 2026

### 🛠 Installer
✅ **Mac installer rewrite**: Replaced the `.zip`-wrapped `Install ReefShape (Mac).app` AppleScript bundle with a plain `Install ReefShape (Mac).command` shell script at the repo root, mirroring the PC `.bat`. The old wrapper had three compounding problems: (1) the zip stripped the executable bit so the `.app` wouldn't launch, (2) the AppleScript ran the inner script via `do shell script with administrator privileges`, which made `$HOME` resolve to `/var/root` and installed scripts to the wrong directory entirely, and (3) the unsigned `.app` triggered Gatekeeper "is damaged" errors that masked the underlying issues. The new `.command` is committed with mode `100755` so both `git clone` and the "Download ZIP" button deliver a runnable file. No `sudo` needed — `~/Library/Application Support/...` is user-writable. First run still prompts Gatekeeper; right-click → Open bypasses it.
✅ **Install hygiene — reinstall is now actually clean**: `Install ReefShape (PC).bat` previously just `xcopy`'d the source over the target, which meant stale `__pycache__` bytecode files and any renamed-or-removed scripts (or `modules/` files) lingered in the install dir indefinitely. The bat now removes `__pycache__/`, `modules/`, and the nine ReefShape `.py` files at the top level before copying. Other `.py` files in the scripts folder (unrelated Metashape scripts the user installed separately) are untouched.

### 🐛 Bug Fixes
✅ **Metashape 2.3 compatibility**: Fixed `exportReport` failing with `NameError: Invalid argument name: include_system_info` on Metashape 2.3. The argument was renamed to `save_system_info` upstream; ReefShape now selects the correct argument name based on the running Metashape version, so the same script works on Metashape 2.0–2.3.
✅ **buildDem / buildOrthomosaic kwargs**: Removed the now-unsupported `flip_x` / `flip_y` / `flip_z` arguments from `buildDem` and `buildOrthomosaic` calls. These were removed in Metashape 2.3 and their values had always matched the defaults, so behavior is unchanged on older versions.
✅ **Python 3.12 SyntaxWarnings**: Metashape 2.3 ships Python 3.12, which warns on invalid escape sequences in regular string literals (e.g. `'\d'`, `'\.'`). Converted the affected regex patterns in `01_full_reefshape_workflow.py` and `ui_components.py` to raw strings. Behavior is identical; the noisy warnings on Metashape startup are gone.
✅ **Dialog freeze in Light/Dark themes**: The Full ReefShape Workflow and Align Timepoints dialogs froze the entire Metashape application when opened with the Light or Dark theme active (Classic worked fine). Cause: `setWindowModality(ApplicationModal)` was called in addition to `QDialog.exec()`, and the application-wide event filter that ApplicationModal installs conflicts with the event filters that Metashape's custom Light/Dark QStyles install. Removed the redundant `setWindowModality` call — `exec()` already provides modal behavior. Dialogs now work in all three themes.
✅ **Boundary creation no longer crashes the workflow on unusual marker labels**: `boundaryCreation()` used `re.search(r'(\d+)', marker.label).group(0)` without guarding against `None` — a single marker with a non-numeric label (e.g. `"REF"`, `"point"`) raised `AttributeError` and aborted the entire workflow. The function now skips markers with no digits in their label and markers with no estimated position, breaks after each corner match (so duplicate-digit labels can't push real corners out of the 4-slice), and returns `True`/`False` so the caller can react.
✅ **Workflow no longer silently logs "Boundary Polygon Created" when it wasn't**: The wrapper used to print success unconditionally even when `boundaryCreation` failed (e.g. corner numbers don't match any marker, scalebar markers numbered 5–8 instead of the default 1–4). Now `runWorkFlow` checks the return value, prints accurate status, tracks `has_boundary` through the export phase, and skips the empty boundary shapefile export (used to create an empty `_boundary/` folder).
✅ **Dialog freeze on workflow error**: When an exception propagated out of the workflow body (e.g. `RuntimeError: Not enough items` from `matchPhotos` with no aligned cameras), `self.setEnabled(False)` was never paired with `setEnabled(True)` and the entire dialog became uninteractive. On macOS Light/Dark themes the title-bar close button is a Qt child widget that also became disabled, so the only recovery was restarting Metashape. `runWorkFlow` and `alignChunks` are now thin wrappers around `_runWorkFlowImpl` / `_alignChunksImpl` that re-enable the dialog and surface the error in a message box on any exception. The user can adjust their inputs and re-click OK, or close cleanly.
✅ **CRS no longer silently overwritten on dialog open**: `loadSettings()` was reapplying the user's last-saved CRS to `chunk.crs` every time the Full Workflow dialog opened — a destructive surprise when reopening a project that already used a different CRS than the user's saved preference. The assignment has been removed; `chunk.crs` now only changes when the user clicks OK. The dropdown's initial selection prefers the chunk's actual CRS, falling back to the saved preference and then to the default, so the dropdown reflects reality.
✅ **First-run dependency install no longer re-runs on every Metashape launch**: Two compounding issues. (1) The "is this package already installed?" check was based on `importlib.util.find_spec(<import_name>)` with a naive distribution-name → import-name mapping (`Werkzeug` → `Werkzeug`, etc.). Distribution names with non-trivial case don't match their lowercase import names, so the check returned False and pip was being asked to reinstall every startup. The check now reads `.dist-info` directories directly via `importlib.metadata.distributions(path=[target])`, which works against canonical distribution names with PEP 503 normalization. (2) `_parse_requirement_names` stripped PEP 508 environment markers from each requirement line but didn't *evaluate* them — so `pywin32==306; sys_platform == 'win32'` always landed in the "requested" set on macOS/Linux, where pip correctly skipped it but the tracking check then saw it as still-missing and re-ran pip. Added `_marker_applies()` which evaluates the marker (via `packaging.markers` when available, falling back to a small regex for the `sys_platform` case ReefShape uses) and skips requirements that don't apply on the current interpreter. Result: on second+ launches with all deps already present, `pip_install()` is a near-instant no-op.
✅ **`pip install` no longer uses `--upgrade`** (Windows DLL-lock fix): On Windows, the `.pyd` extension files in already-installed packages (e.g. matplotlib's `kiwisolver/_cext.pyd`) are memory-mapped by the running Metashape process and can't be deleted until Metashape exits. Any pip operation that tries to delete-and-reinstall them crashes with `PermissionError: [WinError 5] Access is denied`. Without `--upgrade`, pip skips requirements that are already satisfied at the target and only installs the truly missing ones — exactly what we want (the upstream `missing` check already gates the whole block on something actually being absent; `--upgrade` was forcing pip to revisit every listed package and is what triggered the lock conflict). Tradeoff: requirement-pin bumps don't take effect on existing installs; users would need to delete the target dir to force a re-install. This is the right default for an auto-installer that runs at Metashape startup.
✅ **Planet-scale DEM allocation failure on Align-Timepoints chunks** (`chunk.updateTransform()` after marker re-enable): The Full Workflow disables every marker before `matchPhotos` (so a corner marker that drifted between timepoints can't poison alignment) and re-enables them after camera optimization. Re-enabling alone doesn't recompute the chunk transform from the now-enabled reference info — it just flips the enabled flag, and the transform stays at whatever pre-alignment state it had. On chunks that received markers + boundary from Align Timepoints, this left the transform out of sync with the marker reference. Symptom: `chunk.region` (in internal coords) projected to a ~30,460 × 19,889 km bounding box, `resetRegion()` honored that extent, and `buildDem` tried to allocate a 60 billion × 40 billion pixel raster at 0.5 mm/pixel — failing with `MemoryError: bad allocation` after 26 minutes of GPU work. Added the missing `self.chunk.updateTransform()` call right after the re-enable loop. Also added a one-line `chunk.region.size` diagnostic print before mesh build so any future region-explosion issue is visible up-front in the console rather than 25+ minutes later as a cryptic OOM.

### 🧹 Code Cleanups
✅ **Modernized signal/slot connections**: Replaced six remaining uses of the deprecated Qt4-style `QtCore.QObject.connect(widget, QtCore.SIGNAL("clicked()"), …)` syntax with the new-style `widget.clicked.connect(…)` syntax across `01_full_reefshape_workflow.py`, `02_align_chunks.py`, and `ui_components.py`. The new-style syntax is consistent with the rest of the codebase and is forward-compatible with PySide6.
✅ **Dialogs no longer call `exec()` from inside `__init__`**: `FullWorkflowDlg`, `AlignChunksDlg`, and `BoundaryMarkerDlg` previously started their modal event loop from within their own constructor, which is fragile (the dialog is half-constructed when the loop starts) and made the freeze above harder to diagnose. Construction and `.exec()` are now separated: the constructor builds the dialog, and the caller (`run_script()` or the parent dialog) calls `.exec()`. No user-visible behavior change.
✅ **All menu registrations are now idempotent**: Scripts 01, 02, 02a, 05, 06, 07 already called `removeMenuItem` before `addMenuItem` so re-running them in the same Metashape session (or after a rename) didn't duplicate or misroute menu items. Scripts 03, 04, and 08 didn't — they only called `addMenuItem`. Brought all nine into line so the system behaves identically across all of them.
✅ **Cleaner dependency tree — matplotlib dropped, 03's requirements slimmed**: Three related cleanups that drop matplotlib and its fragile dep tree (kiwisolver, pyparsing, cycler, contourpy, fonttools, pillow) entirely from ReefShape's first-run install. (1) 08 (Create Boundary from Photos) previously used matplotlib for one thing: `ax.contour()` marching-squares to trace the boundary polygon. Swapped for `rasterio.features.shapes` — rasterio is already needed by 11 (Gridded Rugosity); the resulting polygon is pixel-edge rather than sub-pixel-interpolated, but for a boundary that starts from a dilated buffer of camera positions the difference is invisible. (2) 11 uses `rasterio.features.rasterize` for the polygon mask — no matplotlib needed. (3) 03's `requirements_txt` was a 50-line list with open3d, scipy, numpy, matplotlib + every transitive dep explicitly pinned. Trimmed to just the three top-level deps (open3d, scipy, numpy) — pip resolves transitive deps from open3d's own metadata, same end result with a much shorter "is anything missing?" check on every Metashape startup. Removed matplotlib from this list entirely — this script never imported it (the pin was defensive). Existing installs aren't disturbed — users who installed matplotlib for other Metashape scripts keep it untouched; new installs just skip it.

### ✨ Workflow Improvements
✅ **Markers suppressed during alignment and optimization**: When the Align Timepoints script brings a previous timepoint's markers into a new chunk, any scale markers that physically shifted between captures can have inconsistent image-space projections, which destabilizes alignment and biases camera optimization. The full workflow now records each marker's enabled state, disables every marker before `matchPhotos` runs, and restores them once camera optimization is complete. Markers are preserved for downstream use (chunk transform, boundary creation, exports) — they just don't get a vote during alignment.
✅ **Optimization check is now manual-aware**: Previously the workflow detected "alignment was already optimized" by comparing the current tie-point count against a value it had saved earlier in the run — which meant the workflow couldn't tell that the user had optimized manually in the GUI and would re-run the optimization. The check now reads `chunk.tie_points.meta` for `optimize/*` keys, which Metashape writes whenever `optimizeCameras` executes (manually or via script). Optimization no longer runs twice.
✅ **DEM auto-resampled after orthomosaic build**: The workflow builds a DEM at the full ortho resolution so the orthomosaic is artifact-free, but the resulting DEM is unnecessarily large for archival. After the orthomosaic is built, the high-res DEM is now replaced with one at 1/4 ortho resolution (rebuilt from the mesh, not resampled). For an ortho at 0.5 mm/px, the stored DEM is now 2 mm/px. Not clipped to the boundary polygon.
✅ **Align Timepoints copies the boundary polygon**: When aligning a new timepoint to a reference chunk, the outer boundary polygon is now copied across along with the marker georeferencing. The full workflow's boundary check has also been tightened: it skips boundary regeneration whenever an OuterBoundary polygon already exists, not just when there are no shapes at all.
✅ **New: ICP-based Align Timepoints**: Added `02a_align_chunks_ICP.py`, an alternative time-series alignment script that uses Iterative Closest Point against either sparse tie points or mesh vertices instead of shared markers. Useful for repeat surveys without ground control. Installs as **ReefShape → Tools → Align Timepoints (ICP)**. Depends on open3d/scipy/numpy/matplotlib, which are installed automatically on first run by a new bundled `modules/pip_auto_install.py` utility — packages land in a user-writable directory beside Metashape's settings so no admin rights are needed and the install survives Metashape upgrades.
✅ **GIS orthomosaic export no longer fails on large plots**: Exporting the JPEG-compressed orthomosaic for GIS use raised `libtiff error: Strip/tile too large for JPEG. Maximum dimension is 65500` whenever the ortho was wider than 65,500 pixels (common at sub-millimeter resolution). The JPEG-in-TIFF spec caps strip dimensions at 65,500 px, but tiled TIFFs aren't subject to the same cap — each internal tile is JPEG-compressed independently. Switched the GIS ortho export to `tiff_tiled=True`. Output looks identical in QGIS / ArcGIS Pro.
✅ **First-run dependency install now shows progress**: When Metashape first loads the ICP timepoint alignment script, `pip_auto_install` has to install ~10 Python packages (open3d, scipy, numpy, matplotlib, transitive deps) which can take 1–2 minutes. Previously Metashape silently froze during this — looked like a hang. The installer now pops a Qt progress dialog explaining what's happening ("ReefShape first-run setup — installing dependencies"), streams pip's `Collecting / Downloading / Installing` output to the label as it goes, and pulses an indeterminate progress bar. Falls back to console-only output if no Qt event loop is available (CLI Metashape).
✅ **New: Create Boundary from Photos** (`ReefShape → Tools → Create Boundary from Photos`): Generates an OuterBoundary polygon by tracing the outline of aligned-camera positions plus the photo footprint and a user buffer (default 0.5 m). Useful when corner markers aren't available — e.g. timepoints aligned by ICP without shared GCPs, or when you want a boundary that follows actual photo coverage rather than the marker-to-marker rectangle. Algorithm: splat camera (X,Y) onto a raster, dilate by `footprint + buffer` with a disk kernel, keep the largest connected component, fill holes, marching-squares the contour. Photo footprint is auto-estimated from camera altitude above the tie-point cloud × sensor FOV, with a user override in the dialog. Uses scipy/numpy/matplotlib (the same packages installed by the ICP script — no new download if you've used that).
✅ **"Align Timepoints" no longer opens the ICP dialog**: Root cause was a Python name collision, not a Metashape menu issue. Both `02_align_chunks.py` and `02a_align_chunks_ICP.py` defined a class named `AlignChunksDlg`. Metashape Pro runs autorun scripts in a *shared* module namespace, so when both scripts have loaded the global name `AlignChunksDlg` refers to whichever ran last — the ICP one. Clicking "ReefShape/Align Timepoints" still invoked `02`'s `run_script` callback (which Metashape captured correctly), but inside that callback the line `dlg = AlignChunksDlg(parent)` performed a name lookup at call time and resolved to `02a`'s ICP class. Renamed the ICP class to `ICPAlignChunksDlg` so there's no collision. Audited every top-level name across all nine scripts; this was the only collision that mattered (other dupes — `label`, `main` in 05/06, `run_script` in 01/02 — were not captured into callbacks in a way that would trigger the same trap).
✅ **`pip_auto_install` now writes to Metashape's native packages dir**: Previously created its own `python-packages/` directory beside Metashape's settings. But Metashape Pro auto-adds `user-packages-py{X}{Y}` (e.g. `user-packages-py312` for Metashape 2.3) to its embedded Python's `sys.path` on startup, so installs there are visible to all scripts without us needing to manually `sys.path.insert`. Switched to that directory, which: (a) avoids a duplicate orphaned packages directory, (b) lets installs from other scripts (Agisoft's own or third-party) be reused rather than re-fetched, (c) survives Metashape upgrades cleanly.
✅ **Graceful handling when boundary creation fails**: At export time, if no OuterBoundary exists in the chunk and TagLab outputs are selected (which clip to the boundary), the user gets a Yes/No prompt — *Yes* exports TagLab uncropped, *No* halts cleanly and re-enables the dialog so the user can uncheck TagLab and re-run, or close the dialog to create a boundary manually (via scripts 06 or 08). If TagLab is unchecked and boundary creation failed, the workflow completes everything else and the final dialog lists what was skipped. The success-summary popup at the very end now becomes a skip-aware warning when any step was bypassed.
✅ **Scalebar path persists across sessions**: The Full Workflow dialog now remembers the last-used scalebar file path via `QSettings` and restores it into the "Scalebar File:" input on the next launch. The restore is gated on the file still existing (no broken paths); the path is still only *used* during the workflow when the Georeferencing dropdown is set to "Yes" (gated by `autoDetectMarkers`), so the restore is harmless when "No" is selected.
✅ **CRS dropdown — pick any system via Metashape's native selector**: Added a *More…* sentinel entry at the end of the Coordinate System dropdown. Selecting it opens Metashape's `getCoordinateSystem` picker. Chosen systems are inserted into the dropdown before *More…*, persist across sessions (stored as a JSON `[name, wkt]` list in QSettings), and don't re-prompt on subsequent picks — selecting *More…* and picking the same CRS just jumps to the existing entry. If the chunk's current CRS isn't in any list, it's surfaced in the dropdown for the session so the UI reflects the chunk's actual state.
✅ **"Current CRS" indicator with pending-change signal**: The Coordinate System label reads `Coordinate System (current: <name>):` and is colored **green** when the dropdown matches `chunk.crs` (no change pending) and **red** when they differ (the chunk's CRS *will* change on OK). The dropdown itself has a tooltip explaining: *"This chunk's CRS will be changed to the currently selected value upon initiating the workflow."* The label text only reflects the chunk's actual state — changing the dropdown re-colors but doesn't rewrite the "current:" string.
✅ **New: Gridded Rugosity** (`ReefShape → Tools → Gridded Rugosity`): Computes per-cell 3D / 2D surface area ratio (rugosity) on a user-selected grid (0.25 m to 5 m, default 1 m, with the chosen size persisted across sessions) within the active chunk's OuterBoundary polygon, and imports the result back into the chunk as a labeled DEM (e.g. `"Rugosity (1.00m grid)"`) alongside (not replacing) the project's real DEM. Optional checkbox also writes the GeoTIFF to a user-selected folder. Like `09_calculate_area_ratio.py`, it uses the full 3D mesh rather than a 2.5D DEM, so overhangs are captured correctly. Unlike that script, it iterates the mesh's triangles exactly once: for each triangle, compute its 3D area and find which cell its centroid falls in; accumulate area per cell; divide by the cell footprint to get per-cell rugosity. An overhang's two stacked slabs both contribute to the same cell's accumulator while the denominator stays at 1 m², so the ratio comes out >1 in the right amount. Grid origin is snapped to multiples of the cell size in shape CRS, so two timepoints with the same boundary polygon produce pixel-aligned rasters that can be subtracted, regressed, or differenced directly in GIS. Unit conversion (chunk-internal units → meters) uses two affine fits from the same 50 calibration vertices — one internal→shape (for centroid projection of all faces), one world→shape (for shape-units-per-meter); the ratio gives meters-per-internal-unit empirically, sidestepping the various subtle issues of trying to extract `chunk.transform.matrix` directly via Metashape's API. Cross-checked against `chunk.transform.scale` and printed in the console for visibility. Includes a live progress dialog that streams phase updates and a determinate progress bar through the (potentially many-second) vertex/face extraction loops. Depends on `numpy` and `rasterio` (new — auto-installed on first run).
✅ **Boundary polygon from photos is now smoothed by default** (8 — `Create Boundary from Photos`): The polygon previously had a "staircase" outline from pixel-edge tracing of the dilated coverage mask. Added Chaikin's corner-cutting algorithm with a user-selectable number of passes (new "Smoothing passes" spinbox; range 0–5, default 2). Each pass replaces every edge AB with two new vertices at 1/4 and 3/4 along it, rounding off sharp corners while preserving the overall shape (the polygon converges to a quadratic B-spline through the original vertices). The dialog's old "Buffer outside coverage (m)" spinbox was removed — the photo footprint alone now controls the dilation; the buffer was mostly compensating for the staircase artifact that smoothing now handles cleanly.
✅ **pip_auto_install: OK/Cancel confirmation before installing**: A new prompt asks the user before pip is invoked, listing the missing packages (truncated to 6 + "and N more" so transitive deps don't blow up the dialog). Lets users defer the install on a flaky network or low battery; cancelling raises a `RuntimeError` that propagates as a normal console traceback, and the prompt reappears on the next script run. Headless Metashape (no QApplication) auto-confirms — there's no way to prompt and the user invoked the script themselves. The progress dialog heading is now script-agnostic ("Installing Python dependencies required by one or more ReefShape scripts") instead of mentioning the ICP script specifically, since other scripts (Create Boundary from Photos, Gridded Rugosity) also depend on the same auto-installer.

### 🎨 Dialog UX Overhaul
✅ **Collapsible panels**: Each panel in the Full ReefShape Workflow dialog (Project Setup, General, Georeferencing, Export) is now collapsible. Implementation is a `CollapsibleGroupBox` subclass of `QGroupBox` — checking/unchecking the title checkbox hides the panel's contents (Qt's default disable-on-uncheck behavior is augmented with a `setVisible(False)` on a single inner content widget so the box visually shrinks to its title strip). The Align Timepoints dialog's panels are collapsible too via the shared base class. Hidden controls remain *readable* — collapsing a panel never excludes its values from being used when you click OK.
✅ **Theme-aware title chevron**: On Classic theme the QGroupBox check indicator renders as a plain checkbox (reads as enable/disable), so panel titles get a ▼/▶ chevron prefix that flips with collapse state to make the intent unambiguous. On Light/Dark themes Metashape's custom stylesheet already renders the indicator as a chevron, so the prefix is skipped to avoid showing two side-by-side. Theme detection uses `QApplication.styleSheet()` length — Classic ships ~190 chars of basic styling, Light/Dark ship ~26k+ chars of full widget styling; a 1000-char threshold cleanly separates them. Each panel also has a tooltip explaining the collapse behavior in plain English for users who don't recognize either indicator.
✅ **State-based collapse + gray defaults**: When the workflow dialog opens, panels collapse themselves based on what's already done in the chunk: Project Setup collapses if the project is saved and the chunk has photos; General collapses if alignment, mesh, DEM, and orthomosaic all exist; Georeferencing collapses if the chunk's markers carry reference info; Export never auto-collapses. Within General, "Enable Generic Preselection" is grayed when tie points already exist (preselection only affects initial alignment); "Mesh Quality" and "Calculate Model Colors" are grayed when a mesh already exists. Grayed controls are still expandable for inspection — they just don't do anything downstream because the work they configure is already done.
✅ **Auto-collapsed sections labeled "Complete"**: When a panel auto-collapses because its work is already done in the chunk, the title gets " | Complete" appended and is colored green so it's immediately obvious *why* the panel collapsed itself rather than the user having to guess. Applies to both the Full ReefShape Workflow dialog (Project Setup, General, Georeferencing) and the Align Timepoints dialog (Project Setup when the active chunk already has photos).
✅ **Export panel split out**: The three export options (Generate Processing Report, Export Uncropped GIS Outputs, Create TagLab Outputs) plus the output folder selector are now in their own *Export* panel rather than being tucked at the bottom of General. Keeps related controls together and makes the workflow's "configure run" → "configure outputs" split visible at a glance.
✅ **Coordinate System moved to Georeferencing**: The CRS row used to live at the top of the General panel; it now lives at the top of the Georeferencing panel (above the "Do you want to input georeferencing information now?" selector). Conceptually the CRS is a georeferencing setting — it tells Metashape how to interpret coordinates in the georef file — so grouping it with the rest of the georef controls is more discoverable.
✅ **Dialog resizes to fit content as panels collapse**: Previously the dialog had a fixed 60%-of-parent minimum height that left empty whitespace below the visible content when panels were collapsed. The minimum height constraint is gone; each panel's `toggled` signal triggers a deferred `_fitToContent()` that reads the inner form's `sizeHint` and calls `resize()` directly (Qt's `adjustSize` doesn't reliably shrink a dialog hosting a QScrollArea, because the scroll area's own sizeHint is small by design). The dialog now shrinks when you collapse a panel and grows back when you re-expand it.
✅ **Full Workflow dialog no longer clips its right edge / horizontal scrollbar on Mac**: The initial width calculation used `frameGeometry()` before the dialog had been shown, which underestimates by the scrollbar gutter width and window chrome. On macOS this was often just enough to force a horizontal scrollbar and clip right-edge labels (e.g. "Adjust Corner Marker**s**"). Switched to `sizeHint()` plus `QStyle.PM_ScrollBarExtent` (the platform's actual scrollbar width) plus a 20-px chrome margin, so the width matches the real form needs.
✅ **Install progress dialog no longer fills the screen horizontally**: Two issues compounded. First the dialog text included a comma-separated list of every missing package — including the long-tail transitive deps — and `QProgressDialog` auto-sized to fit it. Second, even after moving that list out, `QProgressDialog.setLabelText()` calls `adjustSize()` internally on every update and *overrides* `setFixedSize`, so each "Collecting …" line from pip stretched the dialog wider again (Qt warnings showed it trying to set 6,978 px and 10,272 px widths). Replaced `QProgressDialog` with a plain `QDialog` containing a heading label, a status label, and an indeterminate progress bar — its size is fully under our control. Pip's output is also stripped of the `(from -r <huge abs path>)` annotation and hard-capped at 70 chars before being displayed.
✅ **Same sizing/spacing logic applied to Align Timepoints**: The Align Timepoints dialog now uses the same `sizeHint`+scrollbar-extent width calculation, the same `_fitToContent` auto-resize on collapse, and trailing `addStretch(1)` on its inner layouts. The General panel there is also a `CollapsibleGroupBox`. Project Setup was already inheriting collapsibility via the shared base class.

## [v1.2] – June 2025

### ✨ Major Enhancements
✅ **New Installation Procedure**: To make life easier, ReefShape now has installer scripts for Mac and PC that automatically install the scripts for you. You can still install in the previous fashion by copying and pasting the scripts into the Metashape scripts folder.

✅ **Auto-naming of chunks**: When adding new photos in both main scripts (Full ReefShape Workflow and Align Timepoints), the chunk is automatically renamed to match the capture date in the EXIF data of the images. If this is wrong, you can still rename manually!  

✅ **Manual setting of vertex coloring**: Previously, vertex colors were always generated, sometimes adding hours to the processing time. Vertex colors can now be disabled to save time. If they are enabled, a separate progress bar tracks vertex color generation much more accurately.  

✅ **Custom error dialogs**: Introduced a robust `show_error_dialog()` function to cleanly report exceptions through the GUI instead of console output. Also prevents the GUI from freezing upon errors.  

✅ **Generate Report Improvements**: There is now a separate button to export a processing report independently from other exports. The processing report now has a much nicer header as well.  

✅ **Settings saved from last session**: The Full ReefShape Workflow script now saves user settings, so they will stay as they were the last time you ran the script, even if you closed it instead of running it. Less clicks for everybody!  

### 🧠 Behavior Changes

✅ **Auto-georeferencing overhaul**: If no markers are present, the workflow now pre-selects “Yes” for georeferencing input to ensure smoother initial setup. This setting used to be off by default and asked the user whether they were using auto-detectable markers. The prompt now explains what it does more clearly.  

✅ **Coordinate System Improvement**: Now, instead of the script defaulting to local coordinates, it defaults to your last used settings, and only WGS84+EGM96 or local coordinates can be chosen. This mitigates confusion and saves clicking time. If you'd like your data exported in a different CRS, this can be done manually outside of ReefShape.
