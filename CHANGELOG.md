# 🪸 CHANGELOG – ReefShape

## [v1.3] – June 2026

### 🐛 Bug Fixes
✅ **Metashape 2.3 compatibility**: Fixed `exportReport` failing with `NameError: Invalid argument name: include_system_info` on Metashape 2.3. The argument was renamed to `save_system_info` upstream; ReefShape now selects the correct argument name based on the running Metashape version, so the same script works on Metashape 2.0–2.3.
✅ **buildDem / buildOrthomosaic kwargs**: Removed the now-unsupported `flip_x` / `flip_y` / `flip_z` arguments from `buildDem` and `buildOrthomosaic` calls. These were removed in Metashape 2.3 and their values had always matched the defaults, so behavior is unchanged on older versions.
✅ **Python 3.12 SyntaxWarnings**: Metashape 2.3 ships Python 3.12, which warns on invalid escape sequences in regular string literals (e.g. `'\d'`, `'\.'`). Converted the affected regex patterns in `01_full_reefshape_workflow.py` and `ui_components.py` to raw strings. Behavior is identical; the noisy warnings on Metashape startup are gone.
✅ **Dialog freeze in Light/Dark themes**: The Full ReefShape Workflow and Align Timepoints dialogs froze the entire Metashape application when opened with the Light or Dark theme active (Classic worked fine). Cause: `setWindowModality(ApplicationModal)` was called in addition to `QDialog.exec()`, and the application-wide event filter that ApplicationModal installs conflicts with the event filters that Metashape's custom Light/Dark QStyles install. Removed the redundant `setWindowModality` call — `exec()` already provides modal behavior. Dialogs now work in all three themes.

### 🧹 Code Cleanups
✅ **Modernized signal/slot connections**: Replaced six remaining uses of the deprecated Qt4-style `QtCore.QObject.connect(widget, QtCore.SIGNAL("clicked()"), …)` syntax with the new-style `widget.clicked.connect(…)` syntax across `01_full_reefshape_workflow.py`, `02_align_chunks.py`, and `ui_components.py`. The new-style syntax is consistent with the rest of the codebase and is forward-compatible with PySide6.
✅ **Dialogs no longer call `exec()` from inside `__init__`**: `FullWorkflowDlg`, `AlignChunksDlg`, and `BoundaryMarkerDlg` previously started their modal event loop from within their own constructor, which is fragile (the dialog is half-constructed when the loop starts) and made the freeze above harder to diagnose. Construction and `.exec()` are now separated: the constructor builds the dialog, and the caller (`run_script()` or the parent dialog) calls `.exec()`. No user-visible behavior change.

### ✨ Workflow Improvements
✅ **Markers suppressed during alignment and optimization**: When the Align Timepoints script brings a previous timepoint's markers into a new chunk, any scale markers that physically shifted between captures can have inconsistent image-space projections, which destabilizes alignment and biases camera optimization. The full workflow now records each marker's enabled state, disables every marker before `matchPhotos` runs, and restores them once camera optimization is complete. Markers are preserved for downstream use (chunk transform, boundary creation, exports) — they just don't get a vote during alignment.
✅ **Optimization check is now manual-aware**: Previously the workflow detected "alignment was already optimized" by comparing the current tie-point count against a value it had saved earlier in the run — which meant the workflow couldn't tell that the user had optimized manually in the GUI and would re-run the optimization. The check now reads `chunk.tie_points.meta` for `optimize/*` keys, which Metashape writes whenever `optimizeCameras` executes (manually or via script). Optimization no longer runs twice.
✅ **DEM auto-resampled after orthomosaic build**: The workflow builds a DEM at the full ortho resolution so the orthomosaic is artifact-free, but the resulting DEM is unnecessarily large for archival. After the orthomosaic is built, the high-res DEM is now replaced with one at 1/4 ortho resolution (rebuilt from the mesh, not resampled). For an ortho at 0.5 mm/px, the stored DEM is now 2 mm/px. Not clipped to the boundary polygon.
✅ **Align Timepoints copies the boundary polygon**: When aligning a new timepoint to a reference chunk, the outer boundary polygon is now copied across along with the marker georeferencing. The full workflow's boundary check has also been tightened: it skips boundary regeneration whenever an OuterBoundary polygon already exists, not just when there are no shapes at all.
✅ **New: ICP-based Align Timepoints**: Added `02a_align_chunks_ICP.py`, an alternative time-series alignment script that uses Iterative Closest Point against either sparse tie points or mesh vertices instead of shared markers. Useful for repeat surveys without ground control. Installs as **ReefShape → Tools → Align Timepoints (ICP)**. Depends on open3d/scipy/numpy/matplotlib, which are installed automatically on first run by a new bundled `modules/pip_auto_install.py` utility — packages land in a user-writable directory beside Metashape's settings so no admin rights are needed and the install survives Metashape upgrades.
✅ **GIS orthomosaic export no longer fails on large plots**: Exporting the JPEG-compressed orthomosaic for GIS use raised `libtiff error: Strip/tile too large for JPEG. Maximum dimension is 65500` whenever the ortho was wider than 65,500 pixels (common at sub-millimeter resolution). The JPEG-in-TIFF spec caps strip dimensions at 65,500 px, but tiled TIFFs aren't subject to the same cap — each internal tile is JPEG-compressed independently. Switched the GIS ortho export to `tiff_tiled=True`. Output looks identical in QGIS / ArcGIS Pro.
✅ **First-run dependency install now shows progress**: When Metashape first loads the ICP timepoint alignment script, `pip_auto_install` has to install ~10 Python packages (open3d, scipy, numpy, matplotlib, transitive deps) which can take 1–2 minutes. Previously Metashape silently froze during this — looked like a hang. The installer now pops a Qt progress dialog explaining what's happening ("ReefShape first-run setup — installing dependencies"), streams pip's `Collecting / Downloading / Installing` output to the label as it goes, and pulses an indeterminate progress bar. Falls back to console-only output if no Qt event loop is available (CLI Metashape).
✅ **Dependency install no longer re-runs on every Metashape launch**: The "is this package already installed?" check was based on `importlib.util.find_spec(<import_name>)` with a naive distribution-name → import-name mapping (`Werkzeug` → `Werkzeug`, etc.). Distribution names with non-trivial case (`Werkzeug`, `MarkupSafe`, `Pygments`, `Flask`, `Jinja2`) don't match their lowercase import names, so the check returned False, and pip was being asked to reinstall every startup (pip itself was a no-op since the files were already there — but the network/disk scan still added several seconds of latency and triggered the progress dialog every time). The check now reads `.dist-info` directories directly via `importlib.metadata.distributions(path=[target])`, which works against canonical distribution names with PEP 503 normalization. Result: on second+ launches with all deps already present, `pip_install()` is a near-instant no-op.
✅ **New: Create Boundary from Photos** (`ReefShape → Tools → Create Boundary from Photos`): Generates an OuterBoundary polygon by tracing the outline of aligned-camera positions plus the photo footprint and a user buffer (default 0.5 m). Useful when corner markers aren't available — e.g. timepoints aligned by ICP without shared GCPs, or when you want a boundary that follows actual photo coverage rather than the marker-to-marker rectangle. Algorithm: splat camera (X,Y) onto a raster, dilate by `footprint + buffer` with a disk kernel, keep the largest connected component, fill holes, marching-squares the contour. Photo footprint is auto-estimated from camera altitude above the tie-point cloud × sensor FOV, with a user override in the dialog. Uses scipy/numpy/matplotlib (the same packages installed by the ICP script — no new download if you've used that).
✅ **"Align Timepoints" no longer opens the ICP dialog**: Root cause was a Python name collision, not a Metashape menu issue. Both `02_align_chunks.py` and `02a_align_chunks_ICP.py` defined a class named `AlignChunksDlg`. Metashape Pro runs autorun scripts in a *shared* module namespace, so when both scripts have loaded the global name `AlignChunksDlg` refers to whichever ran last — the ICP one. Clicking "ReefShape/Align Timepoints" still invoked `02`'s `run_script` callback (which Metashape captured correctly), but inside that callback the line `dlg = AlignChunksDlg(parent)` performed a name lookup at call time and resolved to `02a`'s ICP class. Renamed the ICP class to `ICPAlignChunksDlg` so there's no collision. Audited every top-level name across all nine scripts; this was the only collision that mattered (other dupes — `label`, `main` in 05/06, `run_script` in 01/02 — were not captured into callbacks in a way that would trigger the same trap).
✅ **Install hygiene — reinstall is now actually clean**: `Install ReefShape (PC).bat` previously just `xcopy`'d the source over the target, which meant stale `__pycache__` bytecode files and any renamed-or-removed scripts (or `modules/` files) lingered in the install dir indefinitely. The bat now removes `__pycache__/`, `modules/`, and the nine ReefShape `.py` files at the top level before copying. Other `.py` files in the scripts folder (unrelated Metashape scripts the user installed separately) are untouched.
✅ **All menu registrations are now idempotent**: Scripts 01, 02, 02a, 05, 06, 07 already called `removeMenuItem` before `addMenuItem` so re-running them in the same Metashape session (or after a rename) didn't duplicate or misroute menu items. Scripts 03, 04, and 08 didn't — they only called `addMenuItem`. Brought all nine into line so the system behaves identically across all of them.
✅ **`pip_auto_install` now writes to Metashape's native packages dir**: Previously created its own `python-packages/` directory beside Metashape's settings. But Metashape Pro auto-adds `user-packages-py{X}{Y}` (e.g. `user-packages-py312` for Metashape 2.3) to its embedded Python's `sys.path` on startup, so installs there are visible to all scripts without us needing to manually `sys.path.insert`. Switched to that directory, which: (a) avoids a duplicate orphaned packages directory, (b) lets installs from other scripts (Agisoft's own or third-party) be reused rather than re-fetched, (c) survives Metashape upgrades cleanly.
✅ **Full Workflow dialog no longer clips its right edge**: The initial width calculation averaged `scroll_area.frameGeometry().width()` and `main_widget.frameGeometry().width()`, both of which are preliminary measurements taken before the dialog is shown and both of which underestimate the real required width. The result was a dialog that was ~20–30 px too narrow, clipping the last characters of right-edge labels and buttons (e.g. "Adjust Corner Marker**s**", "Use default resolutio**n**") and spawning a spurious horizontal scrollbar. Switched to `max()` of the two measurements plus a 30 px safety margin for the scrollbar gutter and window chrome.
✅ **Install progress dialog no longer fills the screen horizontally**: Two issues compounded. First the dialog text included a comma-separated list of every missing package — including the long-tail transitive deps — and `QProgressDialog` auto-sized to fit it. Second, even after moving that list out, `QProgressDialog.setLabelText()` calls `adjustSize()` internally on every update and *overrides* `setFixedSize`, so each "Collecting …" line from pip stretched the dialog wider again (Qt warnings showed it trying to set 6,978 px and 10,272 px widths). Replaced `QProgressDialog` with a plain `QDialog` containing a heading label, a status label, and an indeterminate progress bar — its size is fully under our control. Pip's output is also stripped of the `(from -r <huge abs path>)` annotation and hard-capped at 70 chars before being displayed.

## [v1.2] – June 2025

### ✨ Major Enhancements
✅ **New Installation Procedure**: To make life easier, ReefShape now has installer scripts for Mac and PC that automatically install the scripts for you. You can still install in the previous fashion by copying and pasting the scripts into the Metashape scripts folder.

✅ **Auto-naming of chunks**: When adding new photos in both main scripts (Full ReefShape Workflow and Align Timepoints), the chunk is automatically renamed to match the capture date in the EXIF data of the images. If this is wrong, you can still rename manually!  

✅ **Manual setting of vertex coloring**: Previously, vertex colors were always generated, sometimes adding hours to the processing time. Vertex colors can now be disabled to save time. If they are enabled, a separate progress bar tracks vertex color generation much more accurately.  

✅ **Custom error dialogs**: Introduced a robust `show_error_dialog()` function to cleanly report exceptions through the GUI instead of console output. Also prevents the GUI from freezing upon errors.  

✅ **Generate Report Improvements**: There is now a separate button to export a processing report independently from other exports. The processing report now has a much nicer header as well.  

✅ **Settings saved from last session**: The Full ReefShape Workflow script now saves user settings, so they will stay as they were the last time you ran the script, even if you closed it instead of running it. Less clicks for everybody!  

### 🧠 Behavior Changes

✅ **Auto-georeferencing overhaul**: If no markers are present, the workflow now pre-selects “Yes” for georeferencing input to ensure smoother initial setup. This setting used to be off by default and asked the user whether they were using auto-detectable markers. The prompt now explains what it does more clearly.  

✅ **Coordinate System Improvement**: Now, instead of the script defaulting to local coordinates, it defaults to your last used settings, and only WGS84+EGM96 or local coordinates can be chosen. This mitigates confusion and saves clicking time. If you'd like your data exported in a different CRS, this can be done manually outside of ReefShape.  

✅ **Project Cleanup is now automatic**: At the end of processing (if script finishes correctly with no errors), the script will automatically delete all intermediate products that are not necessary for long-term storage. This includes Key Points, Depth Maps, and Orthophotos.  

✅ **Create chunk & target type placement**: The “Create Chunk” button and “Select Target Type” dropdown are now positioned at the top of the project setup panel for more intuitive access now that chunks can be named automatically.  

### 🐛 Bug Fixes
✅ Fixed issue where `comboRefChunk` and `comboNewChunk` dropdowns did not reflect renamed or newly created chunks.  
✅ Resolved `[None]` entries in damaged marker dropdowns by attaching actual `Marker` objects as `QComboBox` user data.  
✅ Large map exports for DEMs now support the BigTiff standard and no longer error out for files larger than 4GB.  
✅ Prevented chunk label resets when saving the project.  
✅ Prevented crash when no chunks existed by ensuring a default chunk is always initialized.  
✅ Fixed issue where using `Create Scalebars from Targets` from the tools submenu did not update georeferencing upon completion.
